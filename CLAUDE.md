# Людьмак — заметки для Claude

## Игра

Людьмак — монстр-ведьмак, берёт заказы от нечисти на людей. Забег — 5 ночей.

- **Ночь — дом Людьмака** (центральный экран). Уровень Людьмака = лимит заказов за ночь (LEVEL_BY_NIGHT: 1, 2, 3, 3, 4). Монстры по одному подходят к окошку в двери, их уровень + QUEUE_EXTRA. Каждого можно принять или отклонить. Как только лимит набран, очередь сразу заканчивается (окошко закрывается). В ночь с боссом первый монстр приносит заказ на босса. Пока очередь не закончилась, магазин, сумки и дверь закрыты. Потом: сундук → магазин (5 случайных предметов), сумки → укладка рюкзака на сетке, дверь → «На охоту» (или «Переждать день», если заказов нет — сразу к итогам).
- **День:** автобатлер. Враги всех принятых заказов идут одной цепочкой, по одному. На экране боя обе сетки: слева рюкзак героя (как собран ночью), справа сумка врага (фиксированная раскладка из данных, соседство не считается). Пассивные предметы героя срабатывают сами по перезарядке; активные применяются нажатием на предмет в рюкзаке. **Расходники тратятся навсегда:** заряды хранятся на предмете, кончились — предмет исчезает из рюкзака. Враг использует предметы по priority, раскладка на порядок не влияет (снаряды с зарядами, потом основное оружие; щит по перезарядке; мешок при ударе). Внутри заказа следующий враг выходит сам, без подтверждения. Отступить можно только на привале между заказами — это заканчивает день, неустойка за каждый незавершённый заказ. Здоровье героя за день не восстанавливается: ни между врагами, ни на привале между заказами (привал — только пауза «Дальше / Отступить»). Полное здоровье — в начале каждого дня.
- **Рюкзак — сердце игры.** Соседство (касание стороной клетки) по тегам: правила — данные `src/data/synergies.ts`, числа — `SYNERGY` в balance.ts, расчёт — `src/systems/synergy.ts` (`computePower`). Только у героя. Проценты к характеристике складываются, отключение сильнее бонусов, отключённый предмет ни на кого не влияет. В рюкзаке: метки при перетаскивании, подсказка «база / итог / от кого», панель «Сила снаряжения». В бою пересчитывается на лету, когда предмет исчезает. **Слияние** такого же предмета того же уровня: ★2 / ★3 (`STAR_MULT`), в рюкзаке и при покупке.
- **Ночь 5:** заказ на ведьмака приходит первым, отказаться нельзя. Ведьмак уклоняется от первой бомбы: заряд потрачен, урона и оглушения нет (`dodgeFirstBomb` в данных врага).
- **Условия заказчиков** (`src/data/clients.ts`, числа — `CLIENT_REWARD_MULT`, `CLIENT_PENALTY_MULT`, `GHOST_FIRST_HIT_MULT`) действуют только в бою с врагами своего заказа. Запрет предмета — внешнее отключение в `computePower(items, blocked)`: предмет серый и ни на кого не влияет, пересчёт идёт при смене врага. Упырь запрещает отступать, пока его заказ впереди (`BattleSim.retreatBlockedBy`). Кикимора: награда уменьшает платёж по долгу (`resolveNight`). Видно на карточке, на доске и плашкой в бою.
- **Модификаторы врагов** (`src/data/modifiers.ts`, числа — `MODIFIER_STATS`, шанс — `MODIFIER_CHANCE_BY_NIGHT`) выпадают при генерации заказа: `Contract.mods` параллельно `enemies`, `ChainLink.mod`. Не больше одного на врага, у босса нет. Приставка к имени (`enemyName`), значок на портрете в бою.
- **Магазин по ночам:** редкость `tier` 1–3 у предмета, веса `SHOP_TIER_WEIGHTS_BY_NIGHT`, выбор — `src/systems/shop.ts`. Рамка карточки по редкости.
- **Итоги:** награды и неустойки → платёж по долгу (30, 50, 80, 120, 180 монет по ночам). Монеты не уходят в минус. Не хватает на платёж — конец игры. Пережил 5-ю ночь — победа. Продажа: половина суммарной стоимости × доля оставшихся зарядов.
- **Бой детерминирован.** Случайность — только в отдельных предметах (самоурон топора, взрыв шумного от огня) и в модификаторе «Пьяный» (промахи). Глобальную случайность не добавлять.
- **Смерть в бою:** полная неустойка за незавершённые заказы + потеря случайного предмета, забег продолжается.
- **Обучение** — сценарий ночи 1 (`src/data/tutorial.ts`): только леший без «Отказать», фиксированный магазин из 4 предметов без обновления, 14 шагов строго по порядку (`TUTORIAL_STEPS`, номер — `run.tutorialStep`): всё, кроме нужного элемента, затемнено и заблокировано, стрелка и попап (`components/Hints.ts`: сцена в create вызывает `tutorialAttach(scene, resolve)` — resolve(шаг) отдаёт прямоугольник элемента, 'skip' или null; после действия — `tutorialDone`, при смене состояния — `tutorialRefresh`; бой на паузе, пока `tutorialBlocking`). Флаг «пройдено» — `localStorage` (`isTutorialDone` / `markTutorialDone` в state.ts, всё в try/catch), ставится на итогах ночи 1. В меню «Пропустить обучение» — пока не пройдено (на время разработки `TUTORIAL_ALWAYS = true`: обучение всегда и кнопка всегда видна).
- **Ощущения** (`src/config/feel.ts`): цвета цифр по типу, крупные большие удары, тряска на сильных ударах по герою и взрывах, стоп-кадр при смерти врага, баннеры, затемнение между сценами. Переход между сценами — только `goto(scene, key, data)` из ui.ts; первой строкой `create()` — `fadeIn(this)`.
- **Звук** (`src/config/audio.ts` — ключи, `src/config/volume.ts` — громкость каждого звука, `components/Sound.ts` — `sfx`, `playMusic`, «Без звука»): файлы `public/assets/audio/{key}.ogg`, запасной `.mp3`, грузит Boot; нет файла — тишина и строка `[audio]` в консоли. Новый звук — ключ в `SOUND_KEYS` и вызов `sfx(scene, key)` в месте события.

Полный диздок: `docs/designdoc.md`. Роли: пользователь — геймдизайнер (дизайн и баланс), код пишет Claude, арт рисует художница.

## Стек

Phaser 3 + TypeScript + Vite, веб-билд для itch.io. Scale FIT, базовое разрешение 1920×1080.
Команды: `npm run dev`, `npm run build` (tsc + vite build → `dist/`), `npm run typecheck`, `npm run sim` (симуляция боёв без графики: собирается `vite build --ssr` в `.sim/` и запускается node — без новых зависимостей).

Логика в `src/systems/` и `src/config/`, `src/data/` не должна импортировать Phaser — иначе сломается `npm run sim`. Phaser — только в сценах, `ui.ts`, `components/` и `state.ts`.

## Структура

```
src/
  main.ts            — конфиг Phaser, список сцен
  state.ts           — состояние забега: монеты, предметы, очередь у двери, принятые заказы, магазин, итоги дня,
                       флаг обучения (run.tutorial, показанные подсказки, «пройдено» в localStorage)
  ui.ts              — кнопки (со звуками клика и наведения), текст, шапка с «Без звука», подписи предметов,
                       всплывающая сумка врага, переходы goto / fadeIn
  config/balance.ts  — ВСЕ числа баланса (в т.ч. предметов врагов и правила их использования)
  config/feel.ts     — ощущения: длительности, размеры, пороги, цвета цифр (не баланс)
  config/audio.ts    — манифест звуков и музыки (ключи), лимит копий, смена музыки
  config/volume.ts   — громкость: общая (звуки, музыка) и каждого звука и мелодии отдельно
  config/assets.ts   — манифест ассетов (ключ → путь, заглушки) и раскладки экранов: HOME_LAYOUT (под home.png),
                       BACKPACK_LAYOUT, BATTLE_LAYOUT, HINT_LAYOUT, HEADER_LAYOUT, MENU_LAYOUT
  data/*.ts          — предметы героя (с редкостью tier), предметы врагов, враги (размер и раскладка сумки),
                       заказчики (реплики и условия), теги, modifiers.ts — модификаторы врагов,
                       tutorial.ts — сценарий обучающей ночи и тексты подсказок,
                       synergies.ts — правила соседства (одна запись = одно правило) — без чисел
  components/GridView.ts — ОДИН компонент сетки с предметами для всех мест; режимы 'edit' (экран рюкзака: перетаскивание,
                       метки соседства, слияние, страницы «вне сумок»), 'battle' (рюкзак героя в бою, клик применяет), 'view' (сумка врага)
  components/Hints.ts  — обучение: затемнение всего, кроме нужного элемента, стрелка, попап, блокировка остального
  components/Sound.ts  — звуки (sfx с лимитом копий), музыка с плавной сменой, «Без звука»
  systems/backpack.ts  — логика сеток: маски, поворот, проверка размещения (общая для героя и врагов)
  systems/synergy.ts   — соседство и уровень ★: итоговые характеристики, эффекты с источниками, «сила снаряжения»
  systems/contracts.ts — уровень по ночам, генерация очереди монстров с заказами (множители заказчика, модификаторы врагов)
  systems/shop.ts      — ассортимент магазина по ночам (редкость по весам ночи)
  systems/battle.ts    — ВСЯ логика боя (BattleSim) без Phaser: сцена боя только рисует её события;
                       характеристики предметов героя берёт из computePower и пересчитывает при исчезновении предмета
                       и при смене врага (условие его заказа, модификатор); модификаторы, уклонение ведьмака
  systems/random.ts    — случайность без Phaser (для боя, заказов и симуляции)
  sim/simulate.ts      — симуляция баланса (npm run sim): ночь 1 (меч и покупки ночи 1), эталонные сборки REF по ночам
                       (осмысленная — с позициями под соседство; наивная — те же предметы, случайная раскладка),
                       бой по ночам, экономика (доход, платёж, восполнение расходников, бюджет сборки), таблицы
                       влияния каждого условия заказчика и каждого модификатора. Цели баланса — в designdoc, «Баланс»
  scenes/            — Boot, Menu, Home, Shop, Backpack, Battle, Results, GameOver
public/assets/       — арт художницы (PNG) и звуки (audio/*.ogg), см. README
docs/                — дизайн-документ
```

Переходы: Boot → Menu → Home ⇄ Shop / Backpack → (дверь) Battle или Results → Results → Home следующей ночи или GameOver.

## Правила

- Данные игры — только в `src/data/*.ts`.
- Числа баланса — только в `src/config/balance.ts`, с комментарием, что число значит. Длительности, размеры и пороги эффектов — в `src/config/feel.ts`, звука — в `src/config/audio.ts`, громкость — в `src/config/volume.ts`.
- Картинки — только через ключи из `src/config/assets.ts`. Сцены не обращаются к файлам напрямую. Отсутствующий файл → заглушка в Boot под тем же ключом. Координаты элементов дома — в `HOME_LAYOUT`, не в коде сцены.
- Новые зависимости (кроме phaser, typescript, vite) — только с согласия пользователя.
- Делать только то, что попросили на текущий этап; не добавлять фичи и абстракции сверх задачи.
- Не удалять существующие файлы без подтверждения.
- **Не делать git commit** — коммиты делает пользователь сам, даже если в задаче написано «коммить после этапа».
