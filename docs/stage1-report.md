# Людьмак — итоги первого этапа

Сводка для чата, который будет писать промпты второго этапа. Описано состояние кода на 10.11.2026: что сделано, чем результат отличается от изначального промпта первого дня, какие правила приняты в коде и что осталось нерешённым.

Источники правды в репозитории:
- `docs/designdoc.md` — дизайн-документ;
- `CLAUDE.md` — краткие правила для Claude Code;
- `README.md` — запуск, сборка, куда класть арт;
- `src/config/balance.ts` — все числа баланса.

---

## 1. Что есть сейчас

Игра проходится целиком на заглушках: меню → 5 ночей → победа или поражение по долгу. Стек: Phaser 3.90, TypeScript, Vite 6, других зависимостей нет. Масштаб Scale FIT, базовое разрешение 1920×1080.

**Цикл ночи:**
1. **Дом Людьмака** — центральный экран ночи. Монстры по одному показываются в окошке двери. У каждого карточка заказа: заказчик, реплика, враги, награда, неустойка. Кнопки «Принять» и «Отказать».
   - Уровень героя — это лимит заказов за ночь: 1, 2, 3, 3, 4 по ночам. Монстров приходит на 2 больше уровня.
   - Как только лимит набран, окошко сразу закрывается.
   - Пока очередь не закончилась, сундук, сумки и дверь неактивны.
   - На доске «Заказы на сегодня» видны принятые заказы и счётчик «Заказы: N/M».
   - При наведении на врага в карточке или на доске всплывает его сумка.
2. **Магазин** (через сундук): 5 случайных предметов, покупка, продажа за половину цены, обновление ассортимента за 2 монеты (+1 за каждое следующее в ту же ночь). Свои вещи листаются страницами по 18. Купленный предмет сам ложится в рюкзак, если есть место.
3. **Рюкзак** (через сумки): сетка по маске 8×5. Перетаскивание мышью, поворот правой кнопкой (в том числе во время перетаскивания), подсветка места зелёным или красным. Предметы вне сетки в бою не участвуют.
4. **Дверь** → бой («На охоту»). Если заказов нет — сразу итоги («Переждать день»).

**День (бой):**
- Враги всех принятых заказов идут одной цепочкой, по одному.
- Слева портрет Людьмака, его здоровье и рюкзак. Это та же сетка, что собрана ночью.
- Справа портрет врага, его здоровье и сумка — маленькая сетка с фиксированной раскладкой из данных.
- Пассивные предметы героя срабатывают сами: перезарядка видна затемнением прямо на иконке, при срабатывании иконка вспыхивает и покачивается.
- Активные предметы применяются нажатием на сам предмет в рюкзаке. Отдельных кнопок нет.
- **Расходники тратятся навсегда:** заряды хранятся на предмете и не восстанавливаются. Кончились — предмет растворяется и пропадает из рюкзака.
- Сумка врага отображается так же, но нажимать на неё нельзя, только наводить. При смене врага старая сумка уезжает, новая приезжает.
- Внутри заказа следующий враг выходит сам через 0,6 с, без подтверждения.
- Между заказами — **привал**: +25% здоровья и окно «Дальше / Отступить (−N)». Отступить можно только на привале.
- Есть кнопка «Ускорение ×2». Всплывающие цифры и название сработавшего предмета показываются в центре экрана.

**Итоги ночи:**
- По каждому заказу — награда или неустойка, отдельно сколько украл разбойник.
- При смерти теряется случайный предмет из рюкзака.
- Платёж по долгу: 30, 50, 80, 120, 180 по ночам.
- Монеты никогда не уходят в минус. Не хватило на платёж — «Монеты: 0, долг не оплачен» и конец игры.
- Если уровень вырос, итоги пишут «Новый уровень: теперь до N заказов за ночь».
- Пережил ночь 5 — победа.

## 2. Чем результат отличается от изначального промпта первого дня

Изначальный промпт задавал сцену выбора заказа из 2–3 карточек, бой с кнопками активных предметов и врагов, у которых только здоровье, урон и скорость атаки. За четыре доработки многое поменялось.

### По решениям дизайнера

| Было в изначальном промпте | Стало |
| --- | --- |
| Сцена Contract: 2–3 карточки, выбрать один заказ | Сцена Home (дом Людьмака): монстры по одному у окошка, принять или отказать. `ContractScene` удалена. |
| Один заказ за ночь | Уровень героя = лимит заказов: `LEVEL_BY_NIGHT = [1, 2, 3, 3, 4]`. Очередь = уровень + `QUEUE_EXTRA` (2). При наборе лимита очередь сразу заканчивается. |
| Враг = здоровье, урон, скорость атаки | Враг = здоровье + награда + **сумка предметов**. Чем враг бьёт, задают предметы (13 штук, `src/data/enemyItems.ts`). |
| Активные предметы — кнопки с зарядами | Нажатие на предмет прямо в рюкзаке. Рюкзаки героя и врага видны в бою сетками. |
| Заряды на бой | Расходники тратятся навсегда, предмет исчезает. |
| Отступить можно между любыми врагами | Внутри заказа враги идут подряд без паузы. Отступить можно только на привале между заказами. |
| Здоровье между врагами не восстанавливается | Внутри заказа — не восстанавливается. Между заказами — привал, +25% (`HP_RESTORE_BETWEEN_CONTRACTS`). |
| Число врагов в заказе: 2 / 3 / 3–4 / 4 / 2–3 + босс | В каждом заказе по 2 врага (`ENEMY_COUNT_BY_NIGHT`). При полном наборе заказов за день: 2 / 4 / 6 / 6 / 7. |
| Монеты могли уйти в минус | Монеты не ниже 0, при нехватке — «Монеты: 0, долг не оплачен». |
| Список «Твои вещи» уходил за край экрана | Листается страницами по 18. |
| Крестьянин: 30 здоровья, урон 4, атака раз в 2 с | Подобран симуляцией под ночь 1: 42 здоровья, лепёшка 6 урона раз в 1,5 с (две штуки по заряду), вилы 10 урона раз в 2 с. |
| — | Эликсир и щит ослаблены на глаз: эликсир лечит 22 вместо 30, щит даёт блок 5 вместо 6. После этой правки симуляцию не перепроверяли. |
| Логика боя внутри сцены | Чистый модуль `src/systems/battle.ts` без Phaser и скрипт `npm run sim`. |

### По моим решениям (стоит подтвердить или поправить)

- **Стартовый меч.** `START_ITEMS = ['steel_sword']` дан, чтобы первый бой был проходим.
- **Как враг пользуется сумкой.** Враг делает одно действие за раз: берёт первый доступный предмет по `priority` (есть заряды, выполнено условие) и копит замах до перезарядки этого предмета. Поэтому снаряды с зарядами всегда идут раньше основного оружия. Щит работает отдельно по своему таймеру, мешок срабатывает при каждом ударе врага, который ранил героя.
- **Две лепёшки и два флакона святой воды** — это отдельные предметы в сумке, по одному заряду, чтобы каждый исчезал после своего броска.
- **Ночь 5.** Первый монстр в очереди приносит заказ на одного ведьмака (`BOSS_ESCORT = 0`). Принимать его не обязательно.
- **Смерть с несколькими заказами.** Выполненные заказы оплачиваются, за каждый незавершённый — полная неустойка.
- **Рост силы врагов.** Множитель `ENEMY_STAT_MULT_BY_NIGHT = [1, 1.1, 1.2, 1.3, 1.4]` умножает здоровье врагов и силу их предметов.
- **Амулеты.** Пока у них временные эффекты по таймеру: подкова лечит 3 раз в 5 с, ладанка бьёт врага на 10 и героя на 3 раз в 10 с. Настоящий эффект — усиление соседей — ещё не сделан.
- **Реплики заказчиков** написаны мной, по одной на заказчика (`src/data/clients.ts`).
- **Раскладки сумок врагов.** Крестьянин 2×3, разбойник и аристократ 3×2, монах 2×4, стражник 3×4, ведьмак 3×3. Шпага аристократа лежит повёрнутой.
- **Цена продажи** не учитывает оставшиеся заряды: бомба с 1 зарядом продаётся как новая.

## 3. Архитектура и правила кода

```
src/
  main.ts                 — конфиг Phaser, список сцен
  state.ts                — состояние забега (монеты, предметы, очередь, принятые заказы, магазин, итоги дня)
  ui.ts                   — кнопки, текст, шапка, подписи предметов, всплывающая сумка врага
  config/balance.ts       — ВСЕ числа баланса, с комментариями
  config/assets.ts        — манифест ассетов + раскладки экранов: HOME_LAYOUT, BACKPACK_LAYOUT, BATTLE_LAYOUT
  data/items.ts           — предметы героя (имя, режим, категория, теги, форма)
  data/enemyItems.ts      — предметы врагов (имя, режим action/passive/onHit, категория, теги, форма, priority)
  data/enemies.ts         — враги: имя, размер сетки сумки, раскладка предметов
  data/clients.ts         — заказчики и реплики
  data/tags.ts            — теги (fire, silver, alchemy, food, curse) и свойство noisy
  components/GridView.ts  — ОДИН компонент сетки для всех мест, режимы edit / battle / view
  systems/backpack.ts     — логика сеток: маски, поворот, проверка размещения
  systems/battle.ts       — ВСЯ логика боя (BattleSim), без Phaser
  systems/contracts.ts    — уровень по ночам, генерация очереди с заказами
  systems/random.ts       — случайность без Phaser
  sim/simulate.ts         — симуляция баланса
  scenes/                 — Boot, Menu, Home, Shop, Backpack, Battle, Results, GameOver
public/assets/            — арт художницы
```

**Переходы:** Boot → Menu → Home ⇄ Shop / Backpack → (дверь) Battle или Results → Results → Home следующей ночи или GameOver.

**Правила, которые держатся во всём коде:**
- Данные игры — только в `src/data/*.ts`, числа — только в `src/config/balance.ts`. Координаты экранов — в раскладках в `src/config/assets.ts`.
- Картинки — только по ключам из манифеста. Сцены не обращаются к файлам напрямую. Новый предмет, враг или заказчик в данных сам попадает в манифест.
- `src/systems/`, `src/config/`, `src/data/` и `src/sim/` не импортируют Phaser. Иначе сломается `npm run sim`.
- Сцена боя только отображает `BattleSim`: двигает время (`step`), передаёт нажатия (`useActive`, `advance`) и рисует события (`drain()`). Новая боевая механика добавляется в `battle.ts`, и симуляция получает её автоматически.
- Отображение сетки везде одно — `GridView` с режимами `edit` (экран рюкзака), `battle` (рюкзак героя в бою), `view` (сумка врага).
- Boot пишет в консоль предупреждение, если раскладка сумки врага вылезает за сетку или предметы налезают друг на друга.

**Команды:**
- `npm run dev` — игра на http://localhost:5173;
- `npm run build` — `tsc` и сборка в `dist/` (относительные пути, готово для itch.io);
- `npm run typecheck`;
- `npm run sim` — симуляция. Собирается тем же Vite (`vite build --ssr` в `.sim/`) и запускается `node`, новых зависимостей не нужно. Работает около 3 секунд.

## 5. Баланс: ключевые числа сейчас

- **Герой:** 100 здоровья, полное восстановление в начале дня, потолок блока 20. Старт: 20 монет и стальной меч.
- **Долг:** 30 / 50 / 80 / 120 / 180.
- **Награда за заказ** = сумма «цен голов» врагов × `REWARD_MULT_BY_NIGHT` [1.2, 1.15, 1.2, 1.3, 1.4] ± 10%. Неустойка = 50% награды.
- **Враги, здоровье на ночи 1:** крестьянин 42, стражник 55, разбойник 40, монах 50, аристократ 60, ведьмак 160.
- **Предметы героя:**

| Предмет | Цена | Эффект |
| --- | --- | --- |
| Стальной меч | 8 | 6 урона / 1,5 с |
| Серебряный кинжал | 6 | 3 урона / 0,8 с |
| Проклятый топор | 12 | 15 урона / 3 с; с шансом 25% ранит героя на 4 |
| Деревянный щит | 7 | блок 5 / 3 с |
| Факел | 5 | 7 урона / 4 с |
| Краюха хлеба | 3 | лечит 5 / 6 с |
| Серебряная подкова | 5 | лечит 3 / 5 с |
| Ладанка с костями | 5 | 10 урона / 10 с, ранит героя на 3 |
| Бомба «Гром» | 6 | 2 заряда: 25 урона + оглушение 2 с |

| Мандрагора | 7 | 1 заряд: оглушение 4 с |

## 6. Симуляция: последние результаты

Прогон **до** ослабления эликсира и щита, после него не перепроверяли. 500 прогонов на вариант.

**Ночь 1** (1 заказ, 2 крестьянина). Целевые диапазоны дизайнера: (а) только меч — побед ≥ 85%, здоровье 10–25%; (б) меч + лучшая покупка — побед ≥ 95%, здоровье 25–40%; (в) меч + бесполезный предмет — примерно как (а).

| Вариант | Побед | Медиана здоровья |
| --- | --- | --- |
| а) только меч | 100% | 16% ✅ |
| б) меч + эликсир (лучший; тогда лечил 30) | 100% | 76% ❌ |
| меч + бомба (лучший без лечения) | 100% | 58% ❌ |
| в) меч + ладанка | 100% | 10% |

Остальные покупки: второй меч и кинжал — 56%, топор и щит — 52%, масло — 46%, факел и мандрагора — 36%, подкова — 28%, хлеб — 26%.

**Ночи 2–5**, полный набор заказов, «разумная» сборка (`BUILDS` в `src/sim/simulate.ts`):

| Ночь | Заказов / врагов | Побед | Медиана | Минимум |
| --- | --- | --- | --- | --- |
| 2 | 2 / 4 | 100% | 45% | 28% |
| 3 | 3 / 6 | 99,8% | 62% | 0% |
| 4 | 3 / 6 | 100% | 81% | 19% |
| 5 | 4 / 7 | 100% | 68% | 11% |

**Выводы из цифр:**
- Ночи 2–5 слишком лёгкие. Ночь 4 легче ночи 3, ведьмак не страшный. Множитель врагов растёт медленнее, чем сборка героя, а привал добавляет запаса.
- В ночь 1 одна покупка перевешивает всё: дополнительное оружие примерно вдвое сокращает бой, эликсир добавлял 60 здоровья. Перебор около 900 вариантов крестьянина показал, что одними врагами цель (б) не достичь, нужно трогать предметы героя. Эликсир и щит уже ослаблены, но без проверки.
- Бой детерминирован. Случайны только самоурон топора и состав врагов, поэтому в ночь 1 процент побед всегда 0 или 100. Если нужен разброс, нужен источник случайности — это отдельное дизайн-решение.
- Экономику после перехода на уровни и короткие заказы не пересчитывали. Симуляция считает только бой.

## 7. Известные ограничения и долги

- Если вещей очень много (около 30), зона «вне сумок» на экране рюкзака переполняется.
- Сундук, сумки и дверь в доме кликаются по прямоугольникам из `HOME_LAYOUT`, а не по контуру рисунка.
- Неактивные подписи в доме во время очереди лишь чуть тусклее активных.
- Формула частичной неустойки (доля непройденных врагов) теперь фактически не используется: отступить можно только на привале, когда текущий заказ уже выполнен.
- Бот симуляции жмёт активные предметы сразу, а лечение — когда оно не уйдёт впустую. Расходники в каждом прогоне свежие.
- Пока окно игры в фоне, браузер почти не рисует кадры, и бой стоит. На игру не влияет, но мешает автотестам.
- Изменения последней доработки (уровни, привал, модуль боя, симуляция, крестьянин, эликсир и щит, бой без подтверждения) **не закоммичены**.

## 8. Что из диздока ещё не сделано

- **Соседство предметов по тегам** и подсветка соседей при перетаскивании («+2 урон», «Еда испортится»). Теги в данных уже есть.
- **Слияние предметов** ★2 / ★3.
- **Условия заказчиков:** Леший — «Лес не жечь», Гуль — без бомб, Призрак — без шумного, Упырь — без отступления, Водяной — двойная неустойка, Кикимора — платит списанием долга.
- **Модификаторы врагов:** пьяный, в кольчуге, с факелом, набожный, чуткий сон, ветеран.
- Особенности ведьмака из диздока (игнорирует первую бомбу).
- **Обучающая первая ночь:** фиксированный заказ лешего, магазин из 4 предметов, подсказки. Уровень 1 и ровно один заказ для неё уже готовы.
- Ассортимент магазина в зависимости от ночи.

## 9. Рабочие договорённости (передать в промпты)

- **Claude не делает git commit.** Коммиты делает пользователь, даже если в промпте написано «коммить после этапа». Строку про коммиты в промптах лучше не писать.
- Новые зависимости — только с согласия пользователя. Файлы не удалять без подтверждения.
- Делать только то, что перечислено в задаче этапа. Не добавлять фичи и абстракции сверх неё.
- Все новые числа — в `balance.ts` с комментариями, координаты экранов — в раскладках в `assets.ts`.
- Если пользователь говорит «на глаз, без симуляции», симуляцию не запускать.
- Окружение: Windows. Для git нужен `git -c safe.directory=C:/Users/User/Desktop/Ludmak ...` (у папки другой владелец). Только чтение — status, diff, log.
- Формат отчёта, который пользователь просит в каждом этапе: строка «✅ этап» после каждого шага, в конце — что сделано, какие числа проверить, известные ограничения.

## 10. Подсказки для промптов второго этапа

- Боевые механики (соседство, условия заказчиков, модификаторы) добавлять в `src/systems/battle.ts` и в данные. Тогда `npm run sim` сразу покажет их влияние, а сцена боя только нарисует новые события.
- Соседство считается на сетке героя. Логика сеток в `src/systems/backpack.ts`, отображение и подсветка — в `GridView`, это одно место для экрана рюкзака и боя.
- Условия заказчиков удобно хранить рядом с заказчиком в `src/data/clients.ts`, а показывать на карточке в `HomeScene`.
- Перед правками баланса стоит сначала решить пункты из раздела 6: лёгкость ночей 2–5 и нужна ли боям случайность.
